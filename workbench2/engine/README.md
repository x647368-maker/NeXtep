# Android engine integration — stage 10A
Three handoff sources are byte-identical to the stage-7 reference: UnifiedCore, MotionMath, ReceiptBridge. This is one isolated Android library, not the old production app and not a new fake task engine. OwnerLooperPort marshals independent native backend receipts to the caller-owned Android Looper. No worker/periodic timer/injection/production caller is added. Actual Android instrumentation uses only test-side synthetic backend receipts to verify no-admission, cancellation with late task settlement and release order, mismatched-host rejection. Real OEM authorization, task creation/return, focus/input, host death and FrameTimeline performance remain unverified. No production capability is supplied, no APK is delivered. Existing signed field tool remains unchanged.

## Stage 10B: app-owned compositor geometry only
OwnedSurfaceBatch creates its own child layers, uses the public SurfaceControl transaction APIs (API33+), checks buffer usage/identity and applies all geometry together. At most one commit outstanding; rollback is an explicit new transaction, not a cancellation ACK. Detach releases owned handles only after commit. Commit does not establish physical presentation, task identity, or safe buffer reuse. Borrowed parent/buffers remain caller-owned; immutable buffer content is required; no worker or polling. Public corner-radius API is unavailable; nonzero radius is explicitly refused, not disabled in the real product. Stock API35 test uses two solid-color test buffers, independent composed-display pixel sampling, commit waits, mid-flight rollback, swap and detach. No task screenshot replacement, injected task, touch forwarding, production NativePort or OEM admission. No new user APK.

## Stage 10C: dual task receipt boundary
Core independently requires verified resource evidence and explicit tri-state input observations. Gate presence/absence is not proof of blocked/reopened input. Every frame requires observed input blocked; visual/focus publication remains separate. Android instrumentation exercises paired lifecycle, frame coalescing, stale/late receipts, wrong visual/focus and unknown gate release, using synthetic receipts only. Failure drains and returns leases rather than claiming an in-place visual restore. No OEM authorization or backend; no production APK.

## Stationary-card allocation reduction
The core samples one easing value and caches immutable endpoint maps/unchanged interior poses in Flight. Each middle sample still returns a separate complete map in original owner order. Only the moving pair recomputes geometry; no changed dimensions, corners or quality. Android regression checks 20,020 samples, source ordering, identity reuse and cache immutability. Host-side reproducible benchmark (not part of app or AAR): from this directory, `kotlinc src/main/kotlin/workbench2/motion/MotionMath.kt benchmarks/FlightAllocation.kt -include-runtime -d /tmp/wb2-flight.jar`, then `java -Xms256m -Xmx256m -cp /tmp/wb2-flight.jar workbench2.motion.FlightAllocationKt`. Allocation counts compare the previous sampler algorithm and revised sampler with common helpers on the same warmed JVM; not phone ART, CPU, frame timing or energy claims. No OEM access added.
