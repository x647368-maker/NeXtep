3. **明确输入、显示和归还各自的证据。** 初始和退出期间原生输入只在容器范围内管理。首个真实 buffer 与实际焦点就绪后开启任务触控。关闭或异常时先终止局部回调和输入，再完成任务归还，最后释放会话。现有 `RELEASE` 将容器内 `ABSENT` 作为租约结算信号，因此适配层必须先在同一租约中独立看到原任务仍存在且已脱离容器并回到原归属，同时确认操作已终结、没有迟到挂载或清理。仅容器空、回调成功、过期 ACK、真实任务被删除都不能发送已归还回执。出现不确定状态保留恢复义务，禁止盲重试。
4. **最小运行验收**：用独立测试包启动一个已经运行、有可见编辑状态与可滚动内容的任务。在同一显示上记录挂载前后的 task/user/token、真实新 buffer、WindowManager/InputDispatcher 目标及物理点按、拖动、文本和 IME。退出后复查原任务仍活着、回原位置且状态保留，容器/局部输入区/Back 拦截均已释放。另做挂载发出后未完成时杀掉工作台、ACTIVE 后杀掉工作台、分别模拟承载进程死亡与迟到回调。每例从存活的系统侧独立检查任务归还。授权拒绝不得改变任务树或现有 organizer。单任务全过后才做冷启动、双任务和一大四小。

本专项止点：局部系统会话架构已有可复核 AOSP 先例，归还反例和 2.0 接入修复点已定位。PMS110 当前仍缺该生产包可用的系统接口和独立死亡归还权限/契约。后续有效输入为 OEM 对精确固件与包的接口及授权依据，或独立获授权的 AOSP 平台构建。后者仅验证通用机制。无需升级推理模型、增加诊断包或重跑已有 CI。本工作仅更新既有治理档案，无生产文件、分支、PR 或 APK 变更。
