# 台前调度：息屏耗电取证方案（内部诊断）

**用途：定位显示组与休眠状态；不是证明某版本已省电。** 不更改系统、不自动开启工作台、不重启/卸载/安装任何 APK、不读取私人应用内容、不上传数据。

## 首先采集不插线的电量对照

同一台手机在相近网络信号、室温、亮度设置、后台 App 与电池电量下，分别完成：工作台完整退出 30–60 分钟息屏；v0.9.19 四小窗启用 30–60 分钟息屏。记录每段开始/结束电量、平均功耗与温度；至少重复第二轮并交错顺序。充电、USB 连接、游戏、视频播放、弱信号等干扰须注明。**不能将整机电量损失全部归因为模块**。不要为了 A/B 比较而强行安装签名不同的旧版本。

## 然后采集状态快照（Mac + ADB，人工操作）

在 Mac 上安装 Android Platform Tools 并完成 USB 调试授权后，使用 `bash scripts/collect-power-evidence.sh workspace` 采集已启用四小窗的状态，再以 `baseline`、`after-lock` 等标签分别保存。脚本要求恰好连接一台已授权设备，不使用 root，也不写入手机。它只摘取 `dumpsys power`、`dumpsys display`、`dumpsys battery` 的有限字段和已有 NeXtep 日志，结果保存在本地 `power-evidence/`。

**注意：** USB/ADB 自身可能唤醒手机或改变供电状态，故这些输出只能说明采集瞬间的系统状态；不能直接拿 USB 调试时的电量计算真实息屏功耗，也不能把快照当作完整的深睡证明。

特别注意：旧版 NeXtep 日志仅列出尝试的候选 flags，不证明最终采用哪组，必须核对 dumpsys display 的真实状态。\n\n重点核对：实际 Slot Display 的状态、显示组 ID、PowerGroup wakefulness、从息屏到解锁的状态变化、模块是否仍持有不应该连接的 Surface；若系统不给相应字段，标记“无数据”，不进行推测。

## 隐私与发布门槛

提交前打开生成的 .txt，进一步遮挡 UID、包名、窗口/设备标识与任何私人数据（脚本已过滤常见字段但不能保证完全脱敏）。不上传完整 bugreport、logcat 或私钥。需要比较至少两组可重复的息屏功耗，确认解锁速度与四窗触控/任务 ID 不退化，才考虑把省电补丁合入统一分支。PR #16 继续保持草稿，不自动发布。
