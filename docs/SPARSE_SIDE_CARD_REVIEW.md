# 1～3 个侧边小窗等比例放大｜v0.9.26 内测

用户最新截图：左侧只有两个小窗，上下留白明显；希望单/双/三窗增大，但要求主窗尺寸完全不动、画面不拉伸变形、菜单和 + 按钮不能乱飞。

具体算法：
- 手机竖屏、左/右侧栏，1～2 窗每侧水平边距由 8dp 收至 4dp，3窗收至 5dp；卡片高度按每个已存在虚拟显示的原始画面宽高比计算，剩余高度按实际窗口数分配（不能挤进菜单/加号区域）。
- 四窗、顶部横排、手机横屏、N5展开近方屏完全执行原有算法。折叠外屏仍可能沿用紧凑手机配置，需要真机确认。
- Y700 竖屏继续按先前上方紧凑排布，少于四张卡时只用上述更紧的侧边安全留白；末尾添加按钮沿用现有经过边界检查的跟随逻辑。静态/动态壁纸规则不变。
- 一加侧边栏「+」和三点菜单的定位源码未修改，底部保留 44dp 按钮加 12dp 底距共 56dp 的防撞区域。Y700「+」仍会紧跟最后一个小窗，始终在边界内，避免与卡片重叠。
- 纯展示窗口大小变化，不修改虚拟显示本身的尺寸、任务、焦点、触控传输映射、主窗口布局、外部应用隐私或后台监听。

验收阻断：必须通过 Android 编译、大小比例/空隙/防碰撞 JUnit 和真实 HWUI 画面回归，再在一加/平板上确认视觉。若视觉或真机失败，保持 Draft 不面向酷友推广。

## 1～4 小窗动态增加/减少：低成本卡片过渡

- 仅用户实际新增/关闭侧边栏任务（1↔2↔3↔4）时触发一次短动画，时长190ms；使用ColorOS风格的轻快缓出曲线，但不宣称与ColorOS系统原生动画像素级一致
- 先一次性算好卡片最终宽高和位置，再在实时卡片容器上让X/Y以**完全相同的比例**、同一次位移自然过渡至最终状态；不在动画过程中反复更改TextureView大小、重新连接虚拟显示或重新分配应用任务
- 新加入的卡片只在原位短暂淡入/微缩，不能跨过菜单或新建按钮区域“飞进来”；退出的卡片不制造模糊截图
- 如果上一段动画还没结束就又增加一个小窗，可从当前可见位置继续衔接；窗口数量、旋转、折叠形态及布局模式改变不允许带着旧缩放或位移残留
- Y700竖屏的“+”仍紧跟最后一张卡片，但**不参与卡片变焦动画**；一加底部“+”和左上菜单完全沿用原位置
- 如果开启省电模式或关闭系统动画，禁用装饰过渡，不强制解锁/亮屏、不持有WakeLock/线程/后台计时器、不逐帧重排主窗
- **验收**：1→2、2→3、3→4、4→3、快速连续添加、手动进入锁屏/退出/切横屏/切主窗时，不变形、不撞按钮、不留旧变换。真机测温、续航、帧率尚缺，不能声称绝对“零耗电、零卡顿、零发热”

## 2026-11-11 三设备风险闸门（主窗口续接）

- **Ace 7 Pro / PMS110**：本次新增的 190ms 动画仅在该型号、竖屏侧栏、数量确实变化、非省电状态以及系统允许动画时作为测试候选启用。只有原卡片图层等比缩放/位移，不动菜单/加号/主任务或 VirtualDisplay。
- **Find N5**：无论折叠外屏还是展开内屏，本轮新动画均不启用；展开屏同时被原有近方形几何策略排除。现有 N5 平行视窗修复仍需单独真机验收，不得借本次动画覆盖。
- **联想 Y700（ColorOS 16 移植）**：不启用本轮新动画，保留 v0.9.25 的 **8dp 水平边距**、顶端紧凑小窗、末窗加号、横屏与原生壁纸逻辑，不提前套入 4/5dp 的手机收边规则。
- **其他手机**：目前只观察既有布局，动画默认不启动；小窗静态等比适配仍按竖屏紧凑手机几何策略计算，后续需真机逐型号验证。
- 新检查只限制本轮实验，不代表 Ace 已真机验收；若首次新增/快速连续新增出现视觉或触控异常，维持 Draft，使用上版已通过的稳定 APK，不发布给酷友。

- 过去仅根据显示比例排除 N5 展开内屏，折叠外屏可能被误归类为普通手机而启用本轮放大；已修复。

- N5 折叠外屏、展开内屏、Y700 及其他尚未验收的手机静态小窗尺寸都沿用既有算法；一加保留本轮适度放大和 190ms 数量变化动画。
