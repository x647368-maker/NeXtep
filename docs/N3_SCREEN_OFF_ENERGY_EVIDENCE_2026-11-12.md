# OPPO Find N3 / PHN110 · 屏幕关闭耗电专项（2026-11-12）

## 证据，不代表归因
- 用户提供 v0.9.33-dev / Android 16（API 36）两次 15 分钟「电池与发热」诊断截图。
- 第一次 20:03:01–20:18:01，电量 15%→7%，温度 34.7→36.2℃；实际状态采集 20:24:29，因此电量端点并非严格 15 分钟连续测量。
- 第二次 20:25:56–20:40:56，电量 5%→2%，温度 36.6→27.0℃；端点温度骤降与“手机发热”的叙述冲突，ROM 传感器或采样要进一步确认。
- 两组的首尾均为「工作台未开启，小窗=0」，SystemUI 整个进程 CPU 分别累积约 3,128,588ms/1,288s 与 1,050,833ms/928s；这些计数不能解释为台前调度单独用掉相应 CPU 或能耗。
- 另有「黑屏四小时约 90%→0%，持续发热」的用户叙述；尚无同期系统功耗来源、模块关闭对照、电池健康或物理屏深睡证据。

## 本分支仅修明确的代码风险
- 旧代码在工作台**开启**时持续每 500ms 回退检查锁屏状态；某些仍锁屏但物理屏已亮场景，可重新接上挂起的虚拟显示输出。
- 候选策略：锁屏或物理屏关闭时保持原虚拟显示与任务归属，但禁止输出 Surface 恢复；屏幕关闭的兜底检查 15s，锁屏亮屏 4s，正常激活 2s。系统主动事件仍立即检查，解锁恢复不改变原任务。
- 注意：测试中的工作台**未开启**，所以当前证据不能证明上述活跃工作台路径就是严重掉电的根因；本候选亦不能声称已经修复 N3 耗电。
- 改动仅限 SystemUiRuntime、一份纯策略及单元测试，并由完整 Git blob 精确审计历史冻结；**不改 main、不发 APK、不升版本、不减小窗/降画质/冻结进程**。

## 验收前必须补的低成本对照
1. 同 N3、同信号/Wi-Fi/室温、屏幕关闭、拔掉充电线，在电量较高区间做 30–60 分钟 A/B：A 为工作台彻底退出且模块保持安装，B 为工作台正常启用后锁屏。必要时再加禁用该模块且重启的 C 组，以区分系统及其他模块耗电。
2. 把 ColorOS 电池使用详情中的耗电排行与曲线和各次百分比/温度记录下来；如果系统图可见长期无法深睡，考虑只读 power/display 快照（旧草稿 PR #17），但 USB 取证会干扰休眠。
3. 按展开、折叠、锁屏/解锁回归主窗及 0/1/2/3/4 个真实小窗、任务 ID 连续性、Surface 正确恢复、分屏手势和通知栏。
4. 若电池仍四小时几乎耗尽且持续发烫，优先暂停长时间测试，散热并排查整机背景耗电与电池健康，避免反复放电到 0%。
